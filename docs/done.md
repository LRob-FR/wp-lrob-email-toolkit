## v0.6.x — Form theming + fixes (IN PROGRESS)

The 0.6.x milestone is **Form theming + fixes**, delivered across sub-versions. Form theming itself is still ahead; **`0.6.0` was tagged early (2026-06-12) to ship a critical fix** plus everything else already landed this cycle.

- **Fixed (0.6.1): the in-canvas captcha picker on a contact form never saved its choice.** The form editor has two captcha selectors sharing the meta key `_lrob_etk_cf_challenge`: the Advanced-settings combobox (autosaved fine) and the **in-canvas captcha field** dropped into the form body. The latter's `change` handler in `form-fields-editor.js` only refreshed the live preview and returned — it never POSTed the chosen route, and the structure serializer deliberately omits it — so on reload the picker reverted to the old/default challenge. Fixed by having the `[data-captcha-pick]` branch fire a meta save (`lrob_etk_cf_save_meta`, reusing the editor's existing nonce/ajaxUrl) before returning; the PHP handler already allowlisted + coerced that key, so no server change was needed. (Both selectors share the key, so they stay in sync.)

- **Fixed: fatal error on every new user registration (WooCommerce checkout, wp-admin user-add, programmatic `wp_insert_user`).** `UserHooks::seed_user_defaults()` — fired on the `user_register` hook — referenced `UserMeta::CATEGORY_OPT_OUTS`, a constant **removed** when per-category opt-outs were migrated to the list-membership model. Any account creation threw `Uncaught Error: Undefined constant …UserMeta::CATEGORY_OPT_OUTS`, aborting registration (reported live on WooCommerce checkout, `/commander/`). Fix: dropped the obsolete seed (new users default opted-in; list membership / opt-out is managed on the prefs page). The same dead constant in the one-time category→lists migration (`Module.php`) now reads the legacy meta key `lrob_etk_nl_category_opt_outs` by literal string (it's reading pre-migration data), defusing that latent landmine too.

- **Newsletter sends now actually use the SMTP identity chosen on the newsletter — and the test send mirrors the real send.** The per-newsletter **identity** + **From-name** overrides were saved and displayed but **never applied at send time**: both the real send (`SendLoop`) and the **test send** (`SendAjaxController::handle_test_send`) called `wp_mail()` without forcing anything, so everything went out through the *default* SMTP routing. (Only the Reply-To override worked — it's a standard header.) Fixed by forcing the newsletter's identity + From-name around the sends, via a new `MailRouter` API — `force_send(int $identity_id, string $from_name = '')` + `clear_forced_send()` (built on `force_identity()` + a new `force_from_name()`), mirroring the Contact Form's `force_identity` pattern. Both paths fetch the `MailRouter` from the container and wrap the `wp_mail` loop in `try … finally { clear_forced_send() }` (no-op when SMTP is disabled → newsletter still sends via plain `wp_mail`). `force_identity` survives a batch because `reset_current()` never cleared it. The **test send is now identical to the real send** (same identity + From-name + Reply-To; only the `[TEST]` subject prefix differs). Removed the dead `X-Lrob-Etk-From-Name` header (nothing consumed it; From-name now flows through `MailRouter::override_from_name()` + `configure_mailer()`).

- **Newsletter (and contact-form) emails are now routable in SMTP → Routing rules.** The `SourceResolver::SOURCE_NEWSLETTER` constant existed but was **never pushed**, and `known_sources()` only listed *Default* + *WooCommerce* — so newsletter mail resolved as `default` and couldn't be routed, and `contact_form` (already pushed by `SubmitHandler`) wasn't surfaced either. Now: the newsletter send paths (`SendLoop`, `SendAjaxController` test) **and** the double-opt-in `ConfirmationDispatcher` wrap their sends in the `newsletter` source (`SourceResolver::push`/`pop` / `::with`), so an admin can point all newsletter mail at a specific identity via a routing rule — and signup-form confirmations follow the **same** newsletter route (the chosen design). Precedence: a per-newsletter identity (`force_identity`) still wins over the `newsletter` routing rule, which wins over the default. Both the Newsletter and Contact Form modules now register their source into the `lrob_etk_smtp_known_sources` filter when enabled, so *Newsletter emails* / *Contact form emails* appear as routing rows (gated on module activation). Bonus: newsletter sends are now correctly tagged `source: newsletter` in `email.*` events + logs (was `default`).

- **Admin fixes (SMTP card, autosave visibility, logs preview).** Three quality-of-life corrections that shipped in the same cycle: (1) **SMTP "New identity" card** — the *Encryption* and *Force* fixed-select dropdowns were dead before the first save, because the card is cloned from a `<template>` after the page's one-time `initSelectCombos()` pass; the add handler now re-runs the idempotent `lrobEtkControls.initCombos()` after inserting the clone (memory `project_etk_controls_in_head`). (2) **Host auto-preselect** — once an address + password are entered, the empty Host field auto-fills with the best resolving candidate (lowest-priority resolving **MX** preferred, then a resolving preset, then any MX, then the first option) so the user rarely has to type it. (3) **Autosave badge in card footers** — on tall form cards the header "Saved" badge scrolled out of view; a second `.lrob-etk-card-status` now lives in the **footer** (newsletter + signup-form cards), and the list/recipient **audience pickers** now route their `lrob-etk:save-status` events to the card badge too (they autosaved silently before). (4) **Email-log HTML preview** now flexes to fill the modal height instead of a fixed floor. *(Contact Form card footer badge still pending — different autosave path; see todo.md.)*

## v0.5.0 — Branded dark admin theme + accessible front-end forms (shipped 2026-05-31)

Shipped in v0.5.0:

- **Admin spacing + radius tokenization.** 574 `gap`/`padding`/`margin` literals across the 8 admin sheets → `--etk-space-*`. On-grid values (4/8/12/16/24/32) swapped 1:1 (no visual change); off-grid values rounded **down** to the grid (6→4, 10→8, 14→12, 18/20→16, 28→24) for a tighter feel. Scale extended with `--etk-space-7/8/9` (40/48/60px) for large empty-state / hero padding so it stays density-tunable. The 1 leftover literal `border-radius` → `--etk-radius-md`. Sub-4px micro-nudges (1/2/3px), negative pull-ins, and icon-clearance offsets (`padding-right:22/26px`) intentionally stay literal — they're not layout rhythm. **Zero off-grid spacing literals remain.** Done with a scoped, property-allowlisted transform (never touched `border`/`font`/`width`); validated via dead-css scan + brace-balance + visual QA.

- **Single LRob theme — "Deep Glass" (admin).** Replaced the short-lived Light/Dark/Auto switcher with ONE branded dark theme matching the lrob.fr website — decision: a cohesive shared identity over a multi-theme system. So **no** theme toggle, `prefers-color-scheme`, localStorage, or `data-etk-theme` attribute. The palette lives directly in `admin-base.css` token values: dark navy surfaces (`--etk-page-bg #051826` + a 160° gradient via `--etk-page-bg-image` on `#wpbody-content`), solid navy cards (`--etk-card-bg #0a2236`), amber accent (`--etk-accent #ffb700`, black `--etk-on-accent`), brand-blue headings (`--etk-heading #4fb3ec`), full-amber body/table links (`--etk-text-accent #ffb700`), white-on-dark veils, heavier shadows. `admin-base.css` also unconditionally repaints the WP-core chrome that ignores our tokens (`#wpwrap`/`#wpcontent` backdrop, native `input`/`select`/`textarea` + `<option>` popups, `.button`/`.button-primary`/nav buttons, the in-admin contact-form `--lrob-etk-cf-*` preview remap). Idle control borders bumped to `rgba(255,255,255,.40)` to clear WCAG 1.4.11 (≥3:1); text contrast audited AA, AAA on most. **Removed**: `admin/css/admin-themes.css`, `admin/js/etk-theme.js`, `PageHeader::render_theme_switch()`, `HANDLE_THEMES` + `HANDLE_THEME_JS`. Colour chart: `docs/lrob-palette.md`; design mockup: `docs/lrob-theme-mockup.html`. (Cards ship solid; frosted-glass blur is a possible later per-primitive opt-in. Full reference: docs/admin-ui.md "Theme".)

- **Status-colour system consolidated (dedup pass, part 1).** ~40 duplicated status colour blocks — Newsletter (`nl-status` pills, recipients-badge, card-status-msg, import-result), Captcha (test-result), SMTP (host-status), and the generic `status--` pill across Logging/CF/Dashboard — collapsed onto **5 shared, shape-agnostic `.lrob-etk-state--{on,off,fail,pending,info}`** classes (the 5th, `info`/accent, is new). New **`src/Admin/StatusPill.php`** is the single `status value → state` map; it's localized to JS (`lrobEtkNlSend.statusModifiers`) so server-rendered and client-rebuilt (AJAX) pills resolve identically and can't drift. Key principle: **colour decoupled from shape** — shape classes (uppercase pill vs lowercase badge vs result box) stay where they genuinely differ; only colour is shared, so it's faithful (zero intended pixel change) *and* coherent (one definition of "on is this green"). Micro-inconsistencies normalized in passing (e.g. recipients `will-send` badge used solid `accent` → canonical `text-accent`). Bonus: fixed the `"Default (%s)"` duplicate-translator-comment make-pot warning (6 call sites unified). Version bumped to 0.5.0.

The **`test-result` boxes** (SMTP test-send, Dashboard test-email, Logs + Contact-Form storage cleanup) were migrated onto `state--*` in a follow-up, and lost their left-accent bar to match the flat captcha/import boxes — so the whole status/result colour family is now one source (~45 blocks collapsed). `card-status`, banners (`banner-*`/`nl-card-banner`/`from-warning`) and `conn-test` are deliberately **kept** — they're bespoke shapes (border accent + icon colour, or an italic dirty/saving distinction) where `state--*` would split colour across two places and *reduce* coherence.

**Text-inheritance + legibility pass** (part of the theme): `.lrob-etk` sets `color:var(--etk-fg)` so all text inherits the token (not WP's default — root cause of low-contrast labels); base `.lrob-etk a` (non-button) + `.lrob-etk .description` themed (bare links in logs/submissions + helper text); link-text selectors use `--etk-text-accent` (accent stays for fills/borders); `.lrob-etk-set-default` scoped to beat WP `.button-link`; newsletter dashboard tiles lose WP anchor underline.

**Unified field chrome.** Inputs, `.lrob-etk-select`, and `.lrob-etk-combo` now share one 3-step border — idle `--etk-line-strong`, hover new token `--etk-line-hover` (.60), focus white `#fff` + subtle ring (no WP blue glow, achieved by **specificity not `!important`**: the combo's inner input is borderless at all states via `.lrob-etk .lrob-etk-combo-input`, so a WP border can't appear only at rest and shift the text). The free-vs-pick arrow convention is explicit: a bordered separator before the dropdown arrow = free combo (type your own — host / From email / From name), no separator = pick-only (`.lrob-etk-combo--select`).

**SMTP From fields → inherit-default combos** (CF "Success message" pattern). From email / From name each show a single **"Default — &lt;x&gt;"** option (empty value); picking it clears the field so it inherits the live default shown as the placeholder. From-email default = mailbox username (or "WordPress sender" on mail() transport, "mailbox login" before a username); From-name default = site title. Encryption switched from a native `<select>` to `Combobox::render_fixed_select` so it has the dropdown arrow + unified border like the others (JS reads its hidden value input; encryption change still drives the port). Confirm modal danger button solid red; `--etk-danger` strengthened to `#ef3e36` and `--etk-text-danger` realigned to `#ff6b64` (same hue). Status-pill dots/borders; per-page + date-picker dark.

**Newsletter card rework.** Header is one row (status + subject); the bottom **footer is pinned to the card base** (shared `.lrob-etk-card` flex-column + `margin-top:auto`) so cards of different heights line up. Footer layout: **Duplicate** (copy icon) + **Trash/Delete** (trash icon, danger-on-hover) bottom-left; **Test** + **Send/Schedule** (dynamic) bottom-right; the status note ("Click Schedule to confirm", scheduled/sent/overdue, etc.) sits at the **very bottom below the buttons**. Sent-card stats compacted to one wrapping line — `X targeted` head, then `x sent | x opens (y%) | x clicks (y%)` with thin dividers — so a sent card isn't much taller than a draft. Email preview drops the Tablet viewport (modal too narrow to differentiate): Desktop (full width, email bodies self-cap) + Mobile (375px). Unschedule now actually clears the schedule message; the section-nav tabs (Dashboard/Newsletters/Subscribers) no longer inherit the amber link colour (excluded from the base `<a>` rule). Card-footer save-status fades in place (no left-slide from the old width-collapse animation).

**Card-renderer extraction (file-org refactor, no behaviour change).** The four big per-editor card methods moved out of their page classes into dedicated `*CardRenderer` classes, shrinking the page files to chrome + handlers: SMTP `render_card_form` (+ auth/server/from sections + `render_override_dot`) → `SMTP/Admin/IdentityCardRenderer.php` (`SettingsPage` 1354→264 lines); Newsletter list `render_card` (+ `relative_span`/`summarize_picked_lists`/`translate_status`/`default_identity_label`) → `Newsletter/Admin/NewsletterCardRenderer.php` (`NewslettersPage` 1511→749); Contact Form `render_form_card` → `ContactForm/Admin/FormCardRenderer.php` (`FormsPage` 1934→1554); Newsletter signup `render_form_card` → `Newsletter/Admin/SignupFormCardRenderer.php` (`FormsPage` 855→710). Pattern: the page constructs the renderer once and the render-loop delegates; helpers shared with the page's modals were promoted to `public static` and called as `PageClass::…`, card-only helpers moved into the renderer. **Same change also externalised the last inline-JS holdout:** SMTP's ~700-line `<script>` driver → `admin/js/smtp-cards.js`, enqueued + `wp_localize_script`-fed by `SMTP/Admin/PageController::enqueue_assets()` (matching how Newsletter already ships its card JS). No CSS touched.

**Obsolete-page cleanup (card-edited CPTs).** Contact-form and newsletter-signup-form CPTs have no Gutenberg editor (forms are built on their custom admin page), so their default WP screens are dead bare-title relics. Audited + closed the holes: `ContactForm\Admin\PageController` (renamed `redirect_post_type_list` → `redirect_legacy_cpt_screens`) and `Newsletter\FormCPT` (renamed `redirect_post_list` → same) now redirect **all three** obsolete screens — the `edit.php` list, `post-new.php` create, and `post.php?action=edit` — to the custom Forms page (idle GETs only; bulk/save POSTs pass through). The **Dashboard contact-form tile** no longer links its button to the dead `post-new.php` editor: the button now appears **only when 0 forms exist** (an empty-state "New form" CTA → the Forms page) and is dropped once forms exist (the "Manage →" button covers it). Dead code removed: `$cf_new_form_url` (Dashboard) + an unused `$edit_url` (CF card). Also fixed a latent bug — the CF card was missing the `id="form-<id>"` anchor its own "New form" picker navigates to (newsletter card already had it). CPTs that *do* use Gutenberg for body content (newsletters, templates) were left untouched — only their `edit.php` list redirects, never the editor. No orphaned JS/CSS asset files found (every file is still enqueued). Convention recorded in CLAUDE.md.

**Dead-code sweep.** Removed dead `NewslettersPage::format_date()` (zero callers after the renderer split — SubscribersPage has its own) and the dead `.lrob-etk-nl-template-badge` / `.lrob-etk-nl-template-status` CSS rules (no emitter; the dead-css scanner's prefix-peel was blind to them). The rest of the `nl-template-*` family (group/list/row/title/footer) is live (emitted by HomePage). No orphaned asset files.

**Frontend accessibility pass.** Scope decision: admin is deliberately *out* (its drag-and-drop editor is inherently visual, mouse-driven — WCAG there is low-value); the audit targets what real visitors with assistive tech hit. Captcha was already strong (the homemade **math** challenge is screen-reader-friendly by design; the **image** challenge stays intentionally opaque — any descriptive `alt`/`aria` would hand the answer to bots, so math is the accessible alternative; hosted providers ship their own a11y). The actual work landed in the shared `src/Forms/` render + `assets/js/form-submit.js`, so both the **contact form** and **newsletter signup form** benefit: (1) every field's helper + error text is now wired to its control via **`aria-describedby`** (ids derived from the control id, via a shared `describedby_attr()` — covers text/email/textarea/select/number/date/phone/file + radio/checkbox fieldsets); (2) **`aria-invalid="true"`** is toggled on a control when its validation fails (submit-time *and* live file-upload) and cleared on retry, with focus jumping to the first error; (3) the `[data-form-status]` success/error region gained **`role="status" aria-live="polite"`** so outcomes are announced instead of silent. Baseline that was already there: `for`/`id` labels, `required`+`aria-required`, `fieldset`/`legend` for option groups.

**Density — DROPPED.** The real goal (tweak all gaps + font sizes + colours at once) was already delivered by the spacing/font/colour tokenization + the single theme, so a user-facing Compact/Comfortable/Spacious switcher added little. Cut from the milestone.

## v0.4.0 — Modal-everywhere + IMAP cleanup + saved attachments + captcha enrichment + LRob branding (shipped)

Milestone v0.4.x **shipped — tagged `v0.4.0` on 2026-05-29 (GitHub Latest, not pre-release).** **Minimum requirements bumped to PHP 8.2 (8.1 is EOL) + WordPress 6.8.** Note: the admin **spacing tokenization + structural dedup** scoped to 0.4.0 did NOT make the tag — they carried forward as step 0 of v0.5.x (see todo.md). What landed:

### Detail views are modals everywhere (no more dedicated full pages)
- **Email Logs + Contact Form submissions detail = in-page modal only.** The dedicated full-page detail views are gone. `LogViewPage` is now `LogDetailRenderer` (body-only, shared with the AJAX modal endpoint); `SubmissionsPage::render_detail()` removed (kept `render_detail_body()` + the spam/delete email-action confirm pages).
- **Unified detail URL `?…&detail=N`** replaces the ambiguous `action=view&id=N`. Every caller (dashboard activity + CF previews, email "View" links, log↔submission cross-links, newsletter send-sample) uses it; the list pages read it and auto-open the modal. No remapping code.
- Dead full-page code removed: the logging admin-post `resend`/`delete` handlers + `redirect_to_view` (modal uses the AJAX path), the CF inbox JS detail-page redirect branch, 2 orphaned CSS classes.

### IMAP scaffolding purged
- The dormant IMAP "Save to Sent" scaffolding (never built, never read) is gone: `logs.imap_saved` / `imap_error` columns, the `LogEntry` fields, `LogRepository::update_imap_result()`, and every IMAP mention in code comments + README + the plugin header description. Deferred IMAP work still tracked in todo.md.

### SMTP "Save attachments locally" (per identity)
- New per-SMTP-identity toggle (schema: `identities.save_attachments`; v3→v4). **OFF for existing identities, ON by default for new ones.** When on, `Modules/Logging/AttachmentStore` copies each sent attachment under `uploads/lrob-etk-logs/` (`.htaccess` deny, hashed paths — same armature as Contact Form uploads) and rewrites the log row's paths so `Resender::resend()` re-attaches them even after wp_mail's temp files are gone. Copies are purged when the log row is deleted (single / bulk / retention). Resend already worked on any status (incl. successful sends).

### Captcha module enrichment
- **Per-identity widget appearance** — each hosted-provider identity carries its own `theme` (auto / light / dark; auto resolves client-side from `prefers-color-scheme`) + `size` (normal / compact). Schema v4→v6 adds the columns. Rendered via `CaptchaService::resolve_display()` → provider `render()`; admin card preview reflects it live.
- **Cloudflare Turnstile provider** added, sharing a new `Providers/AbstractHostedCaptcha` base with hCaptcha (credential fields, validation, widget render with theme/size/auto, siteverify). Concrete providers carry only constants + branding; the admin preview JS is provider-agnostic (reads widget class + global from localized metadata). reCAPTCHA + invisible mode still pending.
- **"New captcha" creation flow** (was "New identity") — the button now picks the provider up front: a single provider spawns its card directly, several pop a small logo+label menu so the choice is explicit and the card is created already branded for the chosen provider. Replaces the easy-to-miss in-card `<select>` (which never updated the header chip, so picking Turnstile still looked like hCaptcha — the actual cause of "can't choose Turnstile"). New cards smooth-scroll into view. `applyProviderToCard` now re-brands the chip (logo + label) on provider change.
- **"Captcha protection" UI reworked** — replaced the grid of 6 near-identical dropdowns with a prominent site-wide default + per-context overrides split into two groups: this plugin's forms (inherit by default) and WordPress sections (off by default, opt-in). WordPress-native contexts (comments / lost-password / registration) now flip legacy `inherit` → `none` (schema v6 migration) and read "Off (default)".
- **Built-in challenges get a live preview** (ISO with hosted cards) — Math + Picture recognition render their actual frontend markup inline under a "Preview" label (frontend CSS enqueued on the captcha page); subgrid aligns each card's preview row.
- **Homemade challenge rendering unified + compact, identical front / editor / admin.** The Math/Picture challenge markup is now self-contained in `contact-form.css` (`.lrob-etk-cf-challenge` flex-column) so it no longer depends on the `.lrob-etk-form input` scope — that scope-gap is what left the Math answer glued to the right of the question in the settings preview. Label-above-input, short Math field, tight helper spacing everywhere. The admin built-in preview is wrapped in a `.lrob-etk-form` host so the theme CSS vars resolve and it mirrors the live form (incl. dark-theme adaption). Challenge text colours follow the form's `--lrob-etk-cf-*` vars — no hardcoded colours.
- **Google reCAPTCHA — unified v2 + v3 provider** (one menu entry, version chosen in-card, **default v3**). v3 = invisible, score-based: script loaded `?render=key`, frontend `grecaptcha.execute(key,{action})` on submit drops the token in a hidden field, server checks `success` AND `score >= threshold` (per-identity, default 0.5). v2 = classic checkbox / invisible widget, reusing `AbstractHostedCaptcha`. `render()`/`verify()` branch on version; version + score ride in the encrypted credentials blob (no new schema column). The shared credential-field renderer gained `select` + `number` field types to surface the version picker + score. Admin card preview shows an explanatory note for v3 (no widget). v3 frontend lives in `assets/js/form-submit.js` (execute-on-submit, single-use token cleared on error).
- **Provider ordering + modal chooser.** Providers now carry `sort_order()` (`ProviderInterface`); `CaptchaService::hosted_providers()` sorts by it → menu order **hCaptcha, Cloudflare Turnstile, Google reCAPTCHA**. The "New captcha" chooser is now a shared `.lrob-etk-modal` with a card-per-provider grid (logo + label + description), styled like the "New form" picker, replacing the floating menu.
- **reCAPTCHA card polish + always-on default + WP-native rendering fixes.**
  - **v3 "Test score" button** on the card: loads `api.js?render=key`, runs `grecaptcha.execute()`, server siteverifies and returns the raw score → shows "✓ score 0.90 (≥ 0.50)" / "✗ …". Lets admins confirm keys + calibrate the threshold without a live form (`ACTION_TEST_SCORE` + `Recaptcha::test_score()`).
  - **Conditional card fields**: the score field shows only for v3 (label dropped its "(v3)" qualifier); theme/size show only for v2 (v3 has no widget). JS toggles on the version combo.
  - **Equal-height cards**: captcha cards flex-column with footer pinned bottom (`margin-top:auto`) so "Set as default" / "Delete" line up across the row even though Google's card is taller.
  - **Default never goes empty**: deactivating an identity that's the site-wide default sweeps the default back to a built-in (math), mirroring the delete sweep — a captcha is always active.
  - **WP-native contexts fixed** (comments / wp-login register + lost-password): `WpHooks` now enqueues the frontend captcha CSS there and wraps the output in a `.lrob-etk-form` host. Fixes picture-recognition radios showing raw above each icon, options spanning full width (huge scroll), wrong tile size, detached helper text, hosted-widget overflow, and adds bottom margin so the submit button isn't cramped. (Invisible/v3 execute-on-submit in WP-native forms is still a follow-up — those native forms aren't `.lrob-etk-form`.)
- **Login captcha context (WordPress + WooCommerce).** New `Routing::CONTEXT_LOGIN` (opt-in; absent/none = off so existing installs don't suddenly gate login). `WpHooks` renders on `login_form` (wp-login) + `woocommerce_login_form` (WC account) and verifies via the `authenticate` filter (gated to a real `log`/`pwd` POST) for wp-login and `woocommerce_process_login_errors` for WC. CSS enqueued on wp-login + the WC account page.
- **"Use default" for WordPress contexts.** The WP-native routing pickers (comments / login / lost-password / registration) now offer **Use default** (inherit the site default challenge) alongside **Off** and specific challenges — off stays the default placeholder.
- **Narrow-column widget fit.** wp-login columns are ~270px; full-size hosted widgets used to overflow into a horizontal scrollbar. They now scale to fit (`--narrow` wrap → `transform: scale(.88)` + `overflow:hidden`); compact widgets are centered.
- **No more full-page reload on captcha edits.** `handleSaveSuccess` updates the card in place (slug chip, site-key, preview, create→saved buttons, footer default marker) instead of `window.location.reload()` on every autosave — matches the autosave-everywhere rule. (Setting a *default* still reloads — it restyles markers across all cards + the protection section.)
- **hCaptcha invisible mode.** New per-identity size "Invisible" (only offered for providers whose `supports_invisible()` is true — hCaptcha; surfaced provider-aware in both server-rendered cards and JS-spawned ones). `AbstractHostedCaptcha::render` emits `data-size="invisible"` + declarative vendor callbacks + outer-field markers; `assets/js/form-submit.js` intercepts submit, calls the vendor `execute()`, and resumes submission once the token callback fires. Admin card preview shows an explanatory note instead of a (blank) widget for invisible identities. `supports_invisible()` added to `ProviderInterface`. reCAPTCHA + Pro/Enterprise features still out of scope.
- **Stats are all-time** (not 30-day) and shown even at zero; the per-route counter pill is `inline-block` + `nowrap` (fixed a wrap-to-2-lines / "circle" bug from a too-broad `strong { display:block }` rule). Stats remain a tiny daily-bucketed counter table (UPSERT per verify, all contexts), not a log.

### Quick cleanups
- Logging module description trimmed (no IMAP promise). Module descriptions simplified plugin-wide for the dashboard. The always-on Newsletter cron-diagnostic panel is now a conditional banner that only shows when cron is slow/stalled, with Plesk WordPress-Toolkit guidance.

### CSS colour consolidation (theming prerequisite)
- **Every hardcoded colour eliminated from the admin sheets + JS + the frontend form CSS.** ~160 swaps.
